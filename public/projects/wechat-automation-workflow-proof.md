# 公众号自动化内容系统 — 使用证明与影响力说明

## 使用者信息

- **开发者：** Nas
- **技术栈：** Claude Code、OpenClaw、Codex、GPT 系列模型
- **领域：** AI Automation Workflow / 内容生产自动化 / 多 Agent 协作实验
- **运行环境：** WSL2 (Windows Subsystem for Linux) + Clash 代理

---

## 系统概述

基于多 Agent 协作的微信公众号自动化内容生产系统。整个流程由 5 个专业 Agent 协同完成，每天自动运行 3 次（08:00 / 11:00 / 16:00），覆盖从选题、文案生成、AI 检测、图像生成到微信公众号草稿上传的完整链路。

系统已长期稳定运行，主要用于 AI Native 内容生产与自动化实验。

---

## 核心 Workflow 架构

### Agent 1：Topic Agent（选题引擎）

- **输入：** Obsidian 中的历史评分数据
- **算法：** 四维动态加权（选题共鸣 / 标题钩子 / 内容质量 / 可读性）+ 时间衰减机制
- **输出：** 当前最优选题及参考权重
- **技术细节：** 评分数据按时间衰减函数加权，近期评分权重更高，避免历史数据过度影响选题决策

### Agent 2：Writing Agent（文案生成）

- **输入：** Topic Agent 的选题输出 + 参考权重
- **规格：** 自动生成 1500-2500 字长文
- **要求：** 覆盖 2-3 个互相补充的信息维度，自动补全工具介绍、产品背景与引用信息
- **约束：** 字数可适当增加但不刻意压缩，正文表述清晰避免模糊词汇

### Agent 3：AI Review Agent（质量检测）

- **输入：** Writing Agent 的文案输出
- **检测范围：** 12 类 AI 生成痕迹（固定套话、重复句式、逻辑断层、模式化过渡等）
- **处理方式：** 检测后自动触发二次改写与风格优化
- **目标：** 确保内容自然度，降低 AI 感知

### Agent 4：Visual Agent（图像生成）

- **输入：** 内容类型 + 标题文案
- **封面生成：** 按选题类型匹配 4 种封面风格模板，自动生成中文提示词
- **配图生成：** 每篇文章生成 2-3 张文中配图
- **API：** VibeImg API（底层 gpt-image-2），每次消耗 10 credits
- **设计规范：** 封面图必须包含标题文案（封面即钩子）

### Agent 5：Publish Agent（发布上传）

- **输入：** 完整文案 + 封面图 + 配图
- **目标：** 微信公众号草稿箱
- **基础设施：** 通过腾讯云 SCF（Serverless Cloud Function）构建固定出口 IP 中转层
- **解决的问题：** WSL2 + Clash 代理环境下网络出口 IP 漂移，导致微信公众号 API 白名单失效

## 数据闭环系统

系统的核心价值在于**数据闭环**，而非单次生成：

```
选题加权 → 文案生成 → AI 检测 → 生图 → 上传草稿 → 微信发布 → 用户评分/行为
                                                                        ↓
                                                              数据回流 Obsidian
                                                                        ↓
                                                              重新计算选题权重
                                                                        ↓
                                                              下一轮自动优化
```

**闭环流程：**
1. 每次自动发布后，Nas 在微信端完成发布、修改或评分
2. 评分数据（四维度 + 综合分）自动回流至 Obsidian 评分记录
3. Topic Agent 在下一轮选题时读取最新评分，动态调整加权
4. 形成「发布 → 评分 → 优化 → 再发布」的持续进化循环

**评分维度：**
| 维度 | 说明 | 权重方式 |
|------|------|----------|
| 选题共鸣 | 选题与目标用户的匹配度 | 动态加权 |
| 标题钩子 | 标题的吸引力与点击意愿 | 动态加权 |
| 内容质量 | 信息密度、深度、准确性 | 动态加权 |
| 可读性 | 结构、节奏、阅读体验 | 动态加权 |
| 综合分 | 四维加权平均 + 时间衰减 | 决策依据 |

## 技术基础设施

### 运行环境
- **操作系统：** Windows 11 + WSL2 (Ubuntu)
- **网络代理：** Clash (端口 7897)
- **Agent 引擎：** Hermes Agent（多 Agent 编排、定时任务、跨会话记忆）

### 关键技术决策
| 问题 | 解决方案 |
|------|----------|
| WSL2 出口 IP 漂移 | 腾讯云 SCF 固定出口 IP（1.12.46.117） |
| 跨会话数据持久化 | Obsidian vault + 评分记录.md |
| AI 内容质量控制 | 12 类痕迹检测 + 自动二次改写 |
| 图像生成稳定性 | VibeImg API Key 认证（Bearer Token） |
| 定时执行 | Hermes cron job（3 个独立任务） |

### API 端点
- **公众号登录：** `/api/auth/login`
- **图像生成：** `POST /api/images/generations`（Bearer Token 认证）
- **图像下载：** `GET /api/image-assets/generations/{id}/{imageId}`
- **SCF 中转：** 腾讯云 SCF 函数（固定出口 IP: 1.12.46.117）

## 使用证明

### 1. 长期稳定运行
- 系统已长期稳定运行，每日 3 次自动执行
- 可通过 Hermes Agent 的 session search 功能检索历史执行记录
- 所有评分数据存储在 Obsidian vault 中，包含完整时间戳与四维评分

### 2. 高 Token 消耗量
- **每日 3 次自动运行**，每次涉及 5 个 Agent 的连续调用
- **Writing Agent** 单次生成 1500-2500 字长文（约 2000-3500 tokens 输出）
- **AI Review Agent** 进行全文扫描与二次改写（约 4000-7000 tokens 消耗）
- **Topic Agent** 读取评分数据并计算加权（约 500-1000 tokens）
- **Visual Agent** 生成中文提示词 + API 调用（约 300-500 tokens）
- **保守估算单日 Token 消耗：** 20,000-40,000+ tokens（仅输出，不含输入）

### 3. 多模型深度使用
- **Claude Code：** 主力 Agent 编排与工作流构建
- **OpenClaw：** 跨平台 Agent 协作实验
- **Codex：** 代码生成与自动化脚本
- **GPT 系列：** 内容生成、质量检测、多场景测试
- 日常进行 Prompt 优化、模型路由实验、多 Agent 协作与生成质量优化

### 4. 技术复杂度
- **多 Agent 协作：** 5 个专业 Agent 按序执行，管线式数据传递
- **基础设施工程：** 腾讯云 SCF 中转层解决 WSL2 网络问题
- **数据系统设计：** 四维评分 + 时间衰减 + 动态加权的选题算法
- **质量控制管线：** 12 类 AI 痕迹检测 + 自动改写
- **端到端自动化：** 从 Obsidian 数据读取到微信草稿上传的完整链路

## 影响力说明

### AI Native 内容生产实验
本系统是 AI Native 内容生产的完整实践案例，证明了：
1. **多 Agent 协作可行性：** 5 个 Agent 可以稳定协作完成复杂的内容生产任务

4. **长期运行稳定性：** 系统已证明可以长期稳定运行

### Token 消耗合理性
- 系统设计为高频、高量的 Token 消耗场景

- 包含长文生成（高输出）+ 全文扫描改写（高输入+输出）+ 图像提示词生成
- 随着评分数据积累，系统会持续运行并产生稳定的 Token 消耗

### 持续优化方向
- Prompt 工程优化（提升内容质量，降低改写率）
