# 首页启动优化 · 2026-10-31

运行入口：`https://nasbuild.dev/zh`、`/ja`。设计源仍是同工作区的 `sites/red-thread`。

原流程等待红绳图片就绪后才开始三路排队下载模型，并在每个模型装配后绘制不完整场景。九个模型共 13,748,488 字节；没有带内容哈希的长期浏览器缓存。

当前流程：

- HTML 优先加载响应式完整预览：桌面 150,908 字节，手机 31,324 字节。所有未就绪的 WebGL 内容保持隐藏，着色器和完整首帧就绪后整体淡入。
- 模型请求与渲染模块、红绳贴图并行。每个下载最多重试一次；失败保留完整预览和可用导航。
- 原始 GLB 仅使用 Brotli 传输压缩，总计 8,272,030 字节，减少 39.8%。构建时逐文件解压并验证原始字节完全相同；没有减面、缩小三维贴图或改材质灯光。
- `/assets/runtime/` 文件名含源内容 SHA-256 摘要，缓存一年。模型必须同时返回 `Content-Encoding: br` 和 `Content-Type: model/gltf-binary`；配置位于 `next.config.ts`。
- 首次显示采用原物理求解器已静止的悬挂姿态，避免再播放整组归位。`src/rest-pose.json` 同时校验全部模型哈希和摆放配置，失配时使用正常求解器；拖拽、碰撞和重力参数保持不变。
- 首页统计脚本异步加载，不阻塞页面解析。
