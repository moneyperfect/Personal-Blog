# 手机布局与拖动性能（2026-11-01）

手机竖屏使用 S 形红绳、三排九款挂件，按可见屏幕高度排列，单独一行导航。宽屏保留原斜向布局。390×844 与 375×667 的实际场景截图生成两种 WebP 首屏预览，430×932 复用相近比例，避免启动时切换构图。单指可抓取红绳与挂件，保留双指缩放；横竖屏切换重新建立对应悬挂锚点。

## 保护的视觉与交互

- GLB 文件、模型细节、金属/珐琅材质、灯光强度和桌面构图不变。
- 红绳与挂环在三种桌面变形姿态下，优化前后的顶点及法线 Float32 缓冲逐字节一致。
- 重力、摩擦、弹性、120Hz 固定物理步、16 次求解迭代及自适应防穿透采样不变。
- 原有静止休眠、完整场景就绪后展示、并行下载和缓存策略继续生效。

## 减少的开销

红绳缓存不随拉动改变的截面、宽厚、扭转和基础采样；挂环只上传当前使用的顶点，静止时跳过更新。指针命中复用现有物理轮廓，避免每次扫描百万级精细三角形。物理微步复用临时向量。桌面按真实设备像素比渲染（最高 2），取消普通 1× 屏幕强制 1.5× 超采样，保留抗锯齿与手机最高 1.5× 策略。

本机 Chromium、1586×992、相同鼠标拉绳路径的测量（毫秒）：

| 操作 | 优化前平均值 | 优化后平均值 |
| --- | ---: | ---: |
| 红绳更新/帧 | 1.85 | 1.26 |
| 挂环更新/个 | 0.152 | 0.064 |
| 指针命中/次 | 9.15 | 0.55 |

测试姿态的挂环 position 上传从 24,852 减至 8,814 个浮点数，normal 同步减少。物理耗时随碰撞次数和自适应微步数变化，本次不通过降低物理精度换取性能。帧率依赖具体设备，以上是受控本地测量，并非所有设备的帧率承诺。

## 已验证

- 390×844、375×667、430×932 与 844×390，无横向溢出，九款挂件中心均在视口内；竖屏导航高度 40px。
- Chromium CDP 触摸事件：抓取思考者、移动约 33px、正常释放；抓取红绳和回弹；横竖屏往返无数值恢复。
- 桌面真实鼠标大幅拉绳触发 110 次碰撞，无数值恢复。
- 桌面悬挂物理回归：横向往返拖动触发 572 次碰撞，邻近挂件有位移响应；释放后九件全部休眠、动能为零，空闲期间没有额外渲染。
- 构建通过；真实手机硬件与 iOS Safari 尚未实测。
